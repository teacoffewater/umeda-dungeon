## 2026-08-25 詳細地図「トレースできてる？」の指摘
- **教訓**: 「フロアガイドをトレース」と合意したのに、区画と店位置だけ抜いて床はOSM帯を流用した。部分実装を「できた」と見せない。層(床・区画・店)ごとに「どこまでが約束のデータ源か」を明示する
- **技術メモ**: フロアガイドPDFの通路は白ポリゴンではなく「区画列の隙間」。床外形は 区画∪白片 のモルフォロジー閉包(±8m)で再構成できる。飾り帯(路線図)は 40m超×8m未満の細長判定で除去。分断成分は最近接点を幅8m帯で接続
- **検証メモ**: Three.jsのRaycasterは非表示オブジェクトも拾う(visible連鎖を自前で確認する)。詳細モードの範囲判定は外接ボックス不可(V字のくぼみに他施設が入る)→床形状との距離で判定

## 2026-08-25 詳細地図=ガイドそのまま(位置合わせ不要)の理解ミス
- **教訓**: 「二層構造」の核心は座標系の分離だった。詳細地図を実座標に無理に位置合わせして歪ませたのは、ユーザーの「広域と詳細は別物・シームレス不要」を理解していなかったため。ローカルに正しい地図(紙のフロアガイド)はローカル座標のまま使うのが正解で、案内もその中で完結すれば間違えようがない

## 2026-08-25 「本当にトレースした？」再指摘(床がガタガタ)
- **教訓**: 「トレース」と言うなら原本に描かれている線を使う。区画の集合から床を復元(閉包)したのは近似であり、印刷物のきれいな外形線(灰色ストローク・全周1本)がPDF内に存在した。まず「原本にその形の線が無いか」を探すこと

## 2026-09-03 詳細地図が真っ暗になる(「何も表示されない時がある」)
- **原因**: 広域⇔詳細はカメラを900msかけて飛ばすが、`pointerdown` で `camAnim = null` していたため、遷移中に画面に触れると移動が中断し、**座標系の間の何も無い空間にカメラが取り残されていた**(詳細地図は広域から x+1600 離れた専用エリアにある)。せっかちなタップ・二度タップで再現する
- **修正**: 広域⇔詳細の移動には `hard: true` を付け、pointerdown では中断せず `finishCamAnim()` で行き先へ即着地させる。加えて詳細モード中は注視点を地図の実体から一定距離以内に引き戻す(パンで地図を画面外へ追い出せないように)
- **技術メモ**: 引き戻しの基準に外接ボックスは使えない(ホワイティはV字で、ボックスの角には地図が無い)。床の外形点と区画重心を `detailAnchors` に集めて最近傍距離で判定する。許容距離は「いま見えている範囲」(`dist * tan(fov/2)` と aspect から算出)に比例させる
- **検証メモ**: この手の「時々おかしい」はカメラ座標を実測すると一発。`__dbg.camera.position` と詳細地図の外接ボックスを並べて見る。Playwright は遷移中(200ms後)に `mouse.down/up` を撃てば再現できる

## 2026-09-03 傾斜の記録(坂・階段)を実測込みにした
- **技術メモ**: `.sv-row { display: flex }` が `[hidden]` のUA既定に勝つため、調査モードのフォームの行は**一度も隠れていなかった**（「どこへ」「出口番号」「坂」が全種別で出ていた）。`.sv-row[hidden] { display: none }` を足して解消。`hidden` 属性で出し分けるときは、その要素に `display` を当てているCSSが無いか確認する
- **設計メモ**: 斜度は保存しない。2点の `px`・`px2` と高低差から再計算できる派生値で、`convert_survey.py` が座標フレームを変換すると保存済みの値は古くなるため。表示だけ都度計算する
- **現地メモ**: 階段は段数を数えるのが一番速くて正確なので、段数→高低差(段数×0.17m)を自動見積り。坂は2点タップで水平距離が確定するので、高低差を入れれば斜度%が出る
