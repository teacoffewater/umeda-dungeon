# 教訓(ユーザーからの修正を受けて追記)

## 2026-08-23
- **間違いを指摘されたら1行目で認める。** 説明や経緯を先に並べると「有耶無耶にしている」と受け取られる。構成は「認める → 何が間違いか1行 → 正しい答え」。
- **前提を確認せずに書かない。** 「iPhoneで http://<MacのIP>:8931」と書いたが、地下では同一Wi-Fiにいない。`git remote` と GitHub Pages(https://teacoffewater.github.io/umeda-dungeon/)を先に確認していれば最初から正しい案内ができた。
- **回答は端的に。** 結論→理由(箇条書き3つ以内)。仕様書は60行以内、詳細は実装計画へ。「中学生でもわかるように」と言われたら、専門用語を使わず手順で書く。
- **用語や方針を変えたいときは先に提案し、了解を取ってから文書に反映する。** 「px」→「メートル」の言い換えを、提案はしたが文書を変える前に一言確認すべきだった(しれっと直したと誤解された)。
- **質問には聞かれたことだけ答える。** 「1px=1mで足りる?」に対して仕様の話を混ぜて答え、「答えになっていない」と言われた。意味が複数あるなら、それぞれ1行ずつ。
