# 実寸座標系への切替・区域ごとのOSM取り込み・現地調査モード — 設計

日付: 2026-08-23 / 対象: umeda-dungeon @ c217b8c

## 1. 背景

現地で使った結果、施設・通路の位置と形、階層と上下接続、ルート案内の内容、店舗データの全カテゴリに誤りがあり実用に耐えなかった。調査の結論は「個々のデータの誤り」ではなく **座標の土台そのものが歪んでいる** こと。

- アプリの全座標 `mx,my` はFC2手描き案内図(1350×1910px)のピクセル。
- OSM等の実データは `tools/gen_polys.py` 等に4重コピーされた1本のアフィンでこの歪んだ図に投影されている。そのアフィンは南北が東西より24%引き伸ばされ(0.89 vs 1.11 m/px)、`main.js` は 1px=1.05m 固定なので南北距離が約18%過大、角度も最大±6°ずれる。手描き図の局所歪みは未計測。
- 経路グラフ(79ノード/85エッジ)は全部手置きの直線。OSM地下通路(`tools/data/osm_umeda_underground.json`)は床の色塗りにしか使われていない。
- 店舗1,286件は座標を持たず、通路沿いの並び順から等間隔補間。

ユーザーの決定:
- 目標: 間違った案内をしない/梅田に詳しくない人でも使える。現段階はまず **大枠(位置関係と接続)を信用できるものにする**。
- 正解データ: **OSMの地下データ + 自分での現地調査**。
- 進め方: **A. 座標系を実寸にしてから、区域ごとにOSMで置き換える**。その後、サイトに **現地調査モード** を作る。

OSMカバレッジ(2026-08-22 Overpass): B1通路 7.3km、地下店舗 249件、EV 42、階段 53。**B2はほぼ無い(37m)**。区域ポリゴン(shop=mall)あり: Whity、ディアモール、ドーチカ、ekimo、ルクア、サン広場地下通り、そねちか、ガーデンアベニュー。区域別に強い順: Whity(B1通路1.4km) > ディアモール(1.0km) > ドーチカ(300m、店舗40)。三番街・駅前ビル内部・ハービス系はOSMでは直せない。

## 2. ゴール / 非ゴール

ゴール
1. `mx,my` が「原点からの東向き・南向きのメートル(北が上)」になる。旧データ由来の「px」という呼び方は仕様・コメントから廃止し、座標は小数のメートル値として扱う。緯度経度との相互変換は1本の関数で `main.js` と `tools/` の両方から使える。
2. 既存データ(ノード・上下接続・ラベル・店舗エリア・地上ビル等)が新格子へ一括移行され、見た目・経路・検査ツールが移行前と同等に動く。
3. Whity が OSM の通路中心線で置き換わり、`validate_map.py` が通り、店舗の並び順・上下接続・隣接区域との接続が保たれる。同じ手順がディアモール・ドーチカに適用できる。
4. スマホの3Dマップ上でタップして「階段/EV/ESC/壁・行き止まり/通路あり/出口番号/店/メモ」を記録し、JSONで書き出せる調査モード。

非ゴール(今回やらない)
- 階名表示(浅層/中枢層/深層 ↔ B1F/B2F)のモデル変更。調査記録は看板の階名で残すが、ノードのモデルは触らない。
- B2区域の取り込み(OSMに無い)、店舗位置の実形状化、三番街・駅前ビル・ハービス系の修正。
- 調査JSONを自動でマップへ反映するツール(当面はClaudeが読んで手で反映)。
- GPS計測のHTTPS化(下記 5.4 参照。運用で逃げる)。

## 3. フェーズ1: 実寸座標系への切替

### 3.1 変換の一本化 — `geo.js` / `tools/geo.py`

```
LAT0 = 34.702, LON0 = 135.497, OX = 843.39, OY = 944.35   # 原点は旧アフィンの平行移動項を踏襲し数値域を維持
mx = (lon - LON0) * 111320 * cos(LAT0) + OX               # 東向きメートル
my = -(lat - LAT0) * 110950 + OY                          # 南向きメートル(y は南+)
```
- 回転なし・等方・数値1 = 1m(小数可)。関数名は `ll2m`(緯度経度→メートル)と `m2ll`(逆変換)。
- `geo.js`(ESM、`main.js` と将来の調査モードが import)と `tools/geo.py`(`gen_polys.py`/`validate_map.py`/`make_edit_layers.py`/`fetch_district_mosaic.py` が import)に同じ定数を持つ。定数は `tools/data/frame.json` を正とし、JS側は esbuild でバンドルされるので `geo.js` に同値を書き、`tools/geo.py` 起動時に `frame.json` との一致を検査して食い違えば落とす。
- 4ファイルにコピーされた旧アフィン(`MX`/`MY`/`LAT0`)は削除し、旧→緯度経度の逆変換は移行スクリプト内だけに残す。

### 3.2 `main.js` の定数
- `M2W = ([mx,my]) => [(mx-800)*0.5, (my-1100)*0.5]` は据え置き(1 world unit = 2m)。
- `UNIT_M = 2.0`。距離・徒歩分・しきい値はこの1箇所で整合する。
- `FLOOR_Y`、建物高さ、`GROUND_Y` は触らない(縦方向の誇張は表示上の意図)。
- ファイル先頭コメント(案内図トレースの記述)と README の出典・座標系の記述を更新する。

### 3.3 既存データの一括移行 — `tools/migrate_frame.py`(1回きり・実行後は削除してよい)
旧ピクセル座標 → 旧アフィン逆変換 → 緯度経度 → 新メートル座標 を、**ソース内の数値リテラルを書き換える** 形で行う。対象ブロックを列挙し、スクリプトは各ブロックの置換件数を表示、想定外のリテラル形式があれば失敗させる。

| ファイル | ブロック | 形式 |
|---|---|---|
| `main.js` | `ZONES[*].label` | `[x, y]` |
| `main.js` | `NODES` の `S(…)`, `P(…)`, `J(…)` | 引数 `mx, my` |
| `main.js` | `VERTICALS[*].mx/my` | `mx: N, my: N` |
| `main.js` | ホーム定義(L317-322 付近) `mx, my, dir` | `dir` はベクトルなので回転のみ(平行移動しない) |
| `main.js` | `GROUND_BUILDINGS[*].poly` / `.r`, `FILLER_BUILDINGS` | 点列 / `[x1,y1,x2,y2]`(rは4隅を変換して再度bboxにする) |
| `main.js` | スカイビル `PARTS`/`DECK`、JR駅 `STA_MAIN`/`STA_WEST`/`C`、`VIADUCT`、観覧車 `M2W([1122,698])`、`addBldgLabel(name, x, y, …)` 等の `M2W([N, N])` 直書き | 点 |
| `main.js` | `FLOOR_POLYS`(L334-384) | 移行せず `gen_polys.py` で再生成 |
| `shops.js` | `SHOP_AREAS[*].rect` (27件) | `[cx, cy, w, d]`: 中心は変換、幅 w(東西)は ×1.108、奥行 d(南北)は ×0.891(旧pxの実距離に合わせる) |
| `shops.js` | `SHOP_AREAS[*].path` (4件) | 点列 |
| `tools/gen_polys.py` | `HAND_PLATES`, `DISCS`, `CARVE`/`MASK_HOLES` 内の数値 | 点列 / 円(中心変換、半径は平均スケール) |
| `tools/validate_map.py`, `tools/gen_edit_svg.py`, `tools/make_edit_layers.py` | bbox・しきい値の座標定数 | 個別に確認して変換 |

- 角度の扱い: 旧アフィンは約+2.5°回転を含むため、`dir` のような方向ベクトルは2×2部分で回転のみ適用。
- 移行後に `gen_polys.py` を新 `ll2m` で実行して `FLOOR_POLYS` を再生成し、`dump_nodes.mjs` → `validate_map.py` を通す。

### 3.4 検証(フェーズ1完了条件)
- `validate_map.py` 5項目が通る(ホワイトリストの見直しが必要なら理由をコメントで残す)。
- 既知の2点間距離がOSM実測と±5%で一致する(例: 泉の広場 ↔ 東梅田駅 谷町線改札、ディアモール円形広場 ↔ 大阪駅前第1ビル)。移行前は南北で+18%ずれるはず。
- ブラウザで移行前後のスクリーンショットを並べ、施設配置が「2.5°回って南北が縮んだ」以外に崩れていない。
- 既存のルート(例: インデアンカレー → マヅラ)が移行前と同じ通路を通る。

## 4. フェーズ1b: 区域ごとのOSM取り込み — `tools/import_region.py <zone>`

最初は `whity`。以後 `diamor` → `dotica`。

### 4.1 入力
- `tools/data/osm_umeda_underground.json`(必要なら Overpass で再取得するサブコマンドを付ける)。
- 区域ポリゴン: OSM way id を `tools/data/regions.json` に登録(whity=1304559276, diamor=1304559275, dotica=1304559274 …)。ポリゴンは3mバッファして切り出しに使う。

### 4.2 生成
1. 区域内の `highway=footway|corridor|steps` で `level=-1`(levelタグ無しは `tunnel=yes` のみ採用し警告)を集め、交点で分割、端点・交点をノード化。Douglas-Peucker 1.5m で間引き。
2. 新ノードは `J('whity_osm_<n>', mx, my, 'B1')`、エッジは `['a','b', 幅, 'whity']`。幅はOSMの `width` があれば使い、無ければ区域の既定値(whity 6)。各エッジに OSM way id をコメントで残す。
3. `main.js` の NODES/EDGES 内に `// @region whity begin` 〜 `// @region whity end` マーカーを設け、その中を生成物で置換。初回は既存の whity ノード・エッジをマーカー内に移してから実行する。

### 4.3 既存要素の付け替え(自動、結果をレポート表示)
- **区域外へ出るエッジ**: 旧エッジの片端が区域外なら、区域内側の端点を新グラフの最寄りノード(10m以内、無ければ最寄りノードへの短い接続エッジを追加)へスナップ。
- **P(スポット)・S(駅)ノード**: 区域内のものは残し、新グラフの最寄りノードへ接続エッジ(幅は既定)を追加。
- **VERTICALS**: `a`/`b` が消えたノードを指していれば最寄りの新ノードに付け替え。`mx,my` は据え置き(旧位置は移行済み)。
- **SHOP_AREAS の `edges` チェーン**: 旧チェーンの折れ線(移行済み座標)の両端に最も近い新ノード間の最短経路を新チェーンとする。経路長が旧の0.7〜1.5倍から外れたら警告して手動確認。`rect`/`path` 型は触らない。
- **ゾーン帰属**: `gen_polys.py` の区域割当は新エッジの `zone` を使うので追加作業なし。

### 4.4 検証(区域ごと)
- `validate_map.py` が通る。飛び地・はみ出しが出たら区域ポリゴンのバッファかホワイトリストで対処し、理由を残す。
- ブラウザで Whity 内の代表ルート(泉の広場 → 東梅田駅、Whity → 梅田地下道 → 阪急)を引き、隣接区域へつながる。
- 通路形状を Overpass の描画(診断レポートの図)と目視で照合。
- 現地で歩いて確認(フェーズ2の調査モードで記録)。

## 5. フェーズ2: 現地調査モード

### 5.1 目的
地下ではGPSが効かないため、**3Dマップをタップして現地の事実を記録**し、後でClaudeがマップ修正に変換する。今の「編集シート(Illustrator)」ワークフローのスマホ・現地版。

### 5.2 入り方と表示
- `index.html?survey=1` で有効。通常UIのボトムシートは畳み、画面下に調査バーを出す。
- 3Dマップに **メートル格子**(10m線、50m太線、100mごとに `x,y` ラベル)を表示中フロアの高さに描く。格子は `mx,my` そのもの(=実寸)。
- 現在の表示フロアをタップで選ぶ。フロアは **看板の階名** で表示(例: `B1F`, `B2F`)。ゾーンごとの看板階名↔内部フロアの対応表 `SIGN_FLOOR`(例: `sanban: {S1:'B1F', B1:'B2F'}`, `whity: {B1:'B1F'}`)を `main.js` に追加し、記録にはゾーン・看板階名・内部フロアの3つを残す。

### 5.3 記録の操作
- 床をタップ → マーカーを置き、種別を選ぶ: `階段` `EV` `ESC` `壁・行き止まり` `通路あり` `出口番号` `店` `メモ`。
- 2点もの(`壁・行き止まり`, `通路あり`)は2回タップ。
- 任意で一言メモ(テキスト)。`出口番号` は番号入力(例 `H-25`, `東梅田7`)。`EV/ESC/階段` は「どこへ」(看板階名)を選ぶ。
- 記録は `localStorage` に保存。一覧(種別・座標・メモ)から個別削除。
- 書き出し: `navigator.share` があれば共有シート、無ければ JSON をテキストエリアに表示してコピー(ダウンロードはHTTPでは不安定なので使わない)。

### 5.4 GPS(補助)
- **主役は出口番号**。OSMの出口ノード(`tools/data/osm_exits_whity.json` 111点、他駅は Overpass で追加)をメートル座標で持ち、出口番号を記録したら出口位置を記録に自動付与する。
- GPSボタンは `window.isSecureContext && navigator.geolocation` のときだけ表示。取れたら `lat,lon,accuracy` と `geo.js` の `ll2m` で換算したメートル座標を記録に付ける。`http://<MacのIP>` では出ない旨をバーに表示。HTTPS化は別件。

### 5.5 記録フォーマット
```json
{ "version": 1, "exported": "2026-08-30T10:12:00+09:00", "frame": "metric-v1",
  "records": [
    { "id": "r1", "ts": "...", "type": "stairs", "zone": "whity", "floorSign": "B1F", "floor": "B1",
      "m": [1187.2, 948.6], "to": "B2F", "note": "幅広い、上り下り両方" },
    { "id": "r2", "ts": "...", "type": "wall", "zone": "whity", "floorSign": "B1F", "floor": "B1",
      "m": [1180.0, 960.0], "m2": [1180.0, 990.0], "note": "" },
    { "id": "r3", "ts": "...", "type": "exit", "zone": "whity", "floorSign": "B1F", "floor": "B1",
      "m": [1201.3, 930.1], "exit": "H-25", "exitM": [1203.0, 928.4],
      "gps": { "lat": 34.70212, "lon": 135.50090, "acc": 18 } }
  ] }
```
`type`: `stairs | ev | esc | wall | corridor | exit | shop | memo`。`m`/`m2`/`exitM` は `[mx, my]` のメートル座標。

### 5.6 反映
JSONをClaudeに渡す → 記録ごとにマップ修正(ノード移動・エッジ追加/削除・上下接続追加・店舗並び修正)を行い、`validate_map.py` を通してコミット。自動反映ツールは記録が溜まってから検討。

## 6. 実装順序とコミット単位
1. `geo.js` / `tools/geo.py` / `frame.json` 追加(旧アフィン未使用のまま併存) — コミット
2. `migrate_frame.py` 作成 → 実行 → `gen_polys.py` 再生成 → 検証(3.4) — コミット(移行スクリプトは `tools/_archive/` へ)
3. `import_region.py` 作成 → `whity` 取り込み → 検証(4.4) — コミット
4. `diamor`, `dotica` を同手順 — 区域ごとにコミット
5. 調査モード(5.x)— コミット
6. 現地調査 → 記録反映 — 記録ごとにコミット

`floor_audit.py` は S1 を読めないバグがあり、手順2の検証前に正規表現を `(S1|B1|B2)` に直す。

## 7. リスクと対処
- 数値リテラルの書き換え漏れ: 移行スクリプトは対象ブロックごとに件数を表示し、移行後に `grep` で旧座標域の値が残っていないか目視。スクリーンショット比較で崩れを検出。
- OSMの通路がWhityポリゴンからはみ出す/足りない: バッファ3mで調整。足りない部分は旧エッジを残す(スナップで接続)。
- 店舗チェーンの付け替え失敗: 警告を出して手動で `edges` を書く。並び順データは失わない。
- 調査モードの誤タップ: 記録前に種別選択を挟み、一覧から削除できる。
