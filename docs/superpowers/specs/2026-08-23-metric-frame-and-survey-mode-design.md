# 座標を実寸にして、区域ごとにOSMで直し、現地調査モードを作る

2026-08-23

## 何をするか
1. マップの座標を「手描き案内図のピクセル」から「実寸のメートル」に変える。
2. Whity → ディアモール → ドーチカ の順に、通路をOSMの実データで置き換える。
3. 現地でスマホからタップして記録できる調査モードを作る。

## なぜ
- 現地で使ったら、位置・接続・案内・店舗の全部が間違っていた。
- 原因は座標の土台。案内図のピクセルに実データを無理やり投影しているので、南北が24%伸び、距離が最大18%ずれ、通路も全部手置きの直線。
- OSMにはB1の通路7.3km・店舗249件・EV42基が実座標で入っている(B2はほぼ無い)。

## 決めたこと
- 座標 `mx,my` = 原点からの **東向き・南向きのメートル**(北が上、小数可)。「px」という呼び方はやめる。
- 緯度経度との変換は `geo.js`(アプリ用)と `tools/geo.py`(ツール用)の1本だけ。今4ファイルにコピーされている歪んだ変換は捨てる。
- 1 world unit = 2m(`UNIT_M = 2.0`)。見た目の縮尺・フロア間隔・建物高さは今のまま。
- 既存データ(ノード・上下接続・ラベル・店舗エリア・地上ビル)は、スクリプトで一括して新座標に書き換える。手作業なし。
- 区域の置き換えは `tools/import_region.py <区域>`。OSMの区域ポリゴンで通路を切り出し、`main.js` の `// @region <区域>` の中だけを差し替える。隣の区域への接続・駅・上下接続・店舗の並び順は自動で付け替え、怪しければ警告。
- 調査モードは `index.html?survey=1`。メートル格子を表示し、床をタップして「階段 / EV / ESC / 壁・行き止まり / 通路あり / 出口番号 / 店 / メモ」を記録(2点ものは2タップ)。階は看板どおり B1F/B2F で記録。出口番号を入れたらOSMの出口位置を自動で付ける。GPSはHTTPSのときだけ補助で使う。記録はJSONで書き出し、Claudeがマップ修正に反映する。

## やらないこと(今回)
- 階名表示(浅層/中枢層/深層)の見直し
- B2の区域(OSMに無い)、店舗の形の実寸化、三番街・駅前ビル・ハービス系
- 調査JSONの自動反映、HTTPS化

## 順番と確認
| 段階 | 確認 |
|---|---|
| 1. `geo.js`/`geo.py` を作る | 既存の動きは変わらない |
| 2. 全データを新座標へ移行 | `validate_map.py` 5項目が通る。2点間距離がOSM実測と±5%。移行前後の画面で崩れが無い。既存ルートが同じ通路を通る |
| 3. Whity をOSMで置換 | `validate_map.py` が通る。泉の広場→東梅田、Whity→梅田地下道→阪急 のルートが引ける。OSMの図と目視で一致 |
| 4. ディアモール、ドーチカも同様 | 同上 |
| 5. 調査モード | iPhoneで記録→JSON書き出し→1件をマップに反映できる |

段階ごとにコミットする。ビルドは `./node_modules/@esbuild/darwin-arm64/bin/esbuild main.js --bundle --outfile=app.js --format=iife`(`node_modules/esbuild/bin` が欠けているため)。
