# 広域地図/詳細地図の二層構造 — 設計

2026-08-24

## 何をするか
地図を2層に分ける。**広域地図** = 梅田全体。OSM準拠の実位置・簡略形状で、施設の並びと接続だけを見せる。**詳細地図** = 施設ごと。公式フロアガイドをトレースし、店の名前と実位置まで持つ。2層は**接続地点**でリンクする。

## なぜ
- 今のルート案内がデタラメになる根本原因は、店の位置を通路沿いに等間隔で合成していること。詳細地図で実位置を持てば構造的に直る
- 全部を1枚に描いて情報過多になった表示も、広域はスッキリ・詳細は濃く、に分けられる

## データモデル
- **広域**: 今の NODES/EDGES(OSM由来)をそのまま広域グラフとして使う。店は「名前 → 施設(＋詳細地図があれば詳細側の店ID)」だけ。通路沿いの合成配置は廃止(詳細地図が無い施設は当面ドット無し・検索と案内は施設単位)
- **詳細**: `detail/<施設>.js` に `{ floors: [{floor, 輪郭, 通路}], shops: [{id, name, floor, mx, my}], portals: [...] }`。座標は広域と同じ metric-v1(メートル)。フロアは現地の看板名(B1F/B2F)で持つ
- **接続地点(PORTALS)**: `{ id, 広域ノードID, 施設, 詳細側の位置, 種別(通路続き/EV/ESC/階段) }`。施設の出入口・施設間の境界・階の乗換をすべてこれで表す

## 表示(3Dのまま切替)
- 通常は広域。施設をタップ or 一定以上ズームでその施設の詳細モデルに切替(周囲の広域は薄く残す)
- 詳細地図が無い施設は今の表示のまま(段階移行)

## ルート案内の動き(ユーザー指定)
1. スタート → **広域地図でルートを視覚的に提示**し、施設の並びを文で表示
   例:「阪急三番街のインディアンカレー → ホワイティうめだ → 阪神百貨店 → 駅前第4ビルの喫茶サンシャイン のルートで向かいます」
2. 「案内を開始」→ **詳細地図に飛んで**細かい案内(実位置の店で曲がり・通過を案内)
3. 詳細表示中の小さな広域画面は作ってから判断(初版では無し)

## 最初の題材: ホワイティうめだ
- `tools/data/floorguides/whity_floor02.pdf`(実寸・100mスケールバー)と `whity_2016_labeled.pdf`(ベクター・店名テキスト)から輪郭・区画・店名を抽出(`tools/extract_whity_pdf.py`)
- 教訓(rebuild/whity/STATE.md): **ピンク塗りはテナント区画で、床は区画の間の空白**。制御点5点で位置合わせ
- 抽出が難しければ、座標だけ手トレースに切替(スケールは合っているので現実的)

## やらないこと
- 地上出口の表示・案内(地下完結。フェーズ0で撤去済み)
- 全施設の一括詳細化(ホワイティ → ディアモール → ドーチカ → 駅前ビル…と1つずつ)

## 順番と確認
1. 仕様レビュー(この文書) → 2. PORTALS の定義と広域の店ドット廃止 → 3. ホワイティ詳細地図の抽出・表示切替 → 4. 案内の2段階化(広域文+詳細案内) → 5. 現地確認
各段階で validate_map・ブラウザのルート3本(泉の広場→堂島 / 阪急→ハービス / ホワイティ内)・実機を確認して公開する。

## 改訂 2026-08-25: 詳細地図はガイド座標系(位置合わせ廃止)
- 詳細地図は**フロアガイドそのまま**。ガイド自身の座標系・向き・形を使い、実座標(OSM)との位置合わせはしない
- 広域と詳細は根本から別物。シームレスにつなぐ必要はなく、リンク(施設タップ⇄広域に戻る)だけでつながる
- 効果: アフィン補正の歪み・残差(平均8m)が消え、店の位置はガイド上の番号位置そのもの=誤差ゼロ
- 実装: g座標(PDF pt を等方スケールでm換算) / detailGroup(ワールドの遠方 x+1600 に配置) / 出入りでカメラ保存・復帰
- ガイド内ルート案内は「ガイドの通路(区画の隙間)」上のグラフで行う(次段階)
